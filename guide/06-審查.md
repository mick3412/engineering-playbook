## 要做

- [ ] **6.1 自我審查**：看一次完整的 diff，找錯誤、重複和可以簡化的地方
  - 幾種做法：(a) code-review 技能；(b) simplify 技能；(c) engineering:code-review 技能
- [ ] **6.2 第二意見**：重要或有風險的改動請子 agent 或另一個模型審
  - 幾種做法：(a) reality-checker 子 agent；(b) security-review 技能；(c) llm-council（多模型意見，需 API）
  - 審查依風險分級：先問「這個修改可能出什麼錯、該誰抓」，低風險靠自動檢查，人只看高風險（S6-05）
  - 收到審查意見：讀完、重述、查證、判斷，再一項一項改（S6-03，待試）
  - 另開審查代理：不同提示、只能讀、照五項評分表打分並附出處（S6-04，待試）
- [ ] **6.3 規則化**：同樣的審查意見出現第二次，就寫進 lint、測試或專案規則
  - hook 擋下 agent 時，理由裡寫替代做法（S6-02，待試）
