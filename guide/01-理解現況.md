# 1 理解現況

改之前先看懂：程式怎麼組成、要改哪裡、有沒有現成做法。

**這一步要產出：** 現況筆記（要改的檔案、可重用的做法）

## 要做

- [ ] **1.1 讀程式**：從入口追到要改的地方；大範圍搜尋交給子 agent，只拿結論
  - 幾種做法：(a) Explore 子 agent；(b) Trail-code 等程式地圖工具；(c) 直接讀 README 和目錄結構
- [ ] **1.2 功能地圖**：畫出這個功能涉及的檔案、資料和呼叫關係；大專案存成一份 feature map
- [ ] **1.3 重現問題**：先寫出穩定重現 bug 的步驟或測試，確認它現在會失敗
  - 幾種做法：(a) engineering:debug 技能；(b) 寫一個會失敗的測試
- [ ] **1.4 找可重用的做法**：找專案裡已經有的寫法、函式、元件；照著用，不另起爐灶

**這一步可以試的新工具：**
- Trail-code（原名 Graft）（T-01，待試）：用 tree-sitter 把程式畫成地圖（檔案、函式、誰呼叫誰），Claude Code 每次改檔前先查；另存「學到的事」在 .trail/；複查條件：下一支走到 1.1 讀程式 的作品
  - 測試方法：何時：要理解陌生程式碼庫｜怎麼做：畫出程式地圖讓 Claude 查｜看什麼：找到正確函式的速度｜有效＝比直接搜尋快
- REA（Reverse Engineer Anything）（T-03，待試）：看到別的 app 或網站有喜歡的功能，想知道它怎麼運作時；複查條件：下一次要分析一個可以合法分析的軟體時
  - 測試方法：何時：下一次要理解一個沒有原始碼的工具行為｜怎麼做：setup 時逐項看要改的設定，只核准必要的；分析一個允許分析的對象｜看什麼：說明是否正確、改了哪些設定、能否還原｜有效＝得到可驗證的行為說明，設定可以完整還原
- Firecrawl MCP（T-07，待試）：要大量讀取公開網站內容時；複查條件：需要大量讀網站、內建瀏覽器和 curl 不夠用時
  - 測試方法：何時：要大量讀公開網站｜怎麼做：讀 10 頁並確認網站條款允許｜看什麼：內容完整度、是否觸發限制、費用｜有效＝免費額度內完成
- Perplexity MCP（T-08，未採用）：需要附來源的深入研究時；複查條件：有付費預算時
- Graphify（T-21，待試）：要讓 agent 理解大型程式碼庫時；複查條件：接手大型程式碼庫時
  - 測試方法：何時：接手大型程式碼庫｜怎麼做：建知識圖譜後問 5 個問題｜看什麼：答案正確率｜有效＝比直接搜尋準
