# 協作（跨階段）

怎麼交代 agent、怎麼審、什麼時候停下來確認

## 要做

- 省用量的可信做法：一個任務一段對話、要求一次講完、素材先瘦身（CO-13，待試）
- 收尾時不開新方向；待決事項用固定標籤，只列新的或有變動的（CO-14，待試）
- session 結束時產生交接包，一定要有下一步（CO-15，待試）

## 用什麼工具

- **find-skills（vercel-labs/skills）**（T-27）：想找現成技能時。找技能時用 `npx skills find <關鍵字>`（實跑：幾秒列出技能、安裝次數，比 gh 搜尋準）

**這一步可以試的新工具：**
- task-observer（rebelytics）（T-30，待試）：想讓技能和手冊從實際修正中持續改進時；複查條件：下一個作品完成做 8.2 時
  - 測試方法：何時：連續兩個作品｜怎麼做：開著它工作，作品完成時看觀察紀錄｜看什麼：建議中有幾條被採用進手冊或技能｜有效＝至少 2 條被採用
- context-mode（T-32，待查）：長任務中工具輸出塞爆 context 時；複查條件：2026-12-10 或長任務常塞爆 context 時
  - 測試方法：何時：確認授權後的下一個長任務｜怎麼做：開著它跑｜看什麼：context 用量、是否漏掉該看的輸出｜有效＝用量明顯下降且沒漏資訊
- FreeLLMAPI（tashfeenahmed）（T-47，未採用）：—；複查條件：需要大量免費模型呼叫的批次工作時；送之前逐家看資料條款

## 要注意

- 指令太長，技能可能沒被讀到（CO-11）

## 讓品質更好、更獨特

- ★★ 進度看板直接從專案檔推導（CO-09，待試）

## 背景知識

- 信任曲線不能跳級（CO-01）
- 一個 agent 負責一塊工作，不是一件事（CO-03，待試）
- 工程師像主廚：設計廚房，不親自炒每道菜（CO-07）
- 不信任就會變成微管理（CO-08）
- 高品質的輸入會帶出高品質的輸出（CO-10）
- 交代 AI 寫目標不寫步驟，學方法不學口氣（CO-12，待試）
- 前期 token 投資換長期產能（CO-02，參考）
- 多 agent 各守本分、看得懂誰先誰後（CO-04，參考）
- 複製 bot 會保留人設但清空記憶（CO-05，參考）
